## 3.2 Skill 接口规范（概览）

每个 Skill 是一个独立、可替换的功能单元，负责完成一类确定的元数据处理任务。为了便于编排与复用，每个 Skill 应遵守统一的接口契约（manifest + 运行约定）：

- 必要元数据（manifest 简要字段）
  - name: Skill 名称（如 `author-extraction`）
  - version: 语义化版本号
  - description: 一句话说明 Skill 做什么
  - inputs: 期望的输入类型（例如 `raw_pdf`, `text_segment`, `reference_string`）
  - outputs: Skill 产出的类型（例如 `authors_list`, `affiliations`, `references`）
  - config: 可选配置（模型开关、阈值、��参数）
  - healthcheck: 健康检查端点或方法
  - metrics: Skill 将上报的关键指标（延时、错误率、抽取置信度分布等）

- 运行契约（行为约定）
  - 接口方式：HTTP REST / gRPC / 内嵌函数调用（必须在 manifest 指明）
  - 输入输出格式：JSON Schema（必附最小示例）
  - 错误与重试：当 Skill 无法解析输入时必须返回标准错误码并提供可用于重试的提示（例如缺少 OCR 结果标记）
  - 幂等性：对同一输入多次调用应产生相同可重复的输出（允许非确定性内部模型，但应保证输出可比性与置信度）

- 编排器契约
  - 每个 Skill 的 manifest 将被编排器读取，编排器按 manifest 指定的 I/O 将 Skill 串联成流水线
  - 编排器应支持条件分支（例如：当 pdf2text 输出置信度低时，触发 OCR Skill）

> 注：下面的 Skill 列表与描述是高层摘要，便于在文档读者内建立整体概念；具体实现细节、算法与评测将在 3.4、5、6 节中给出。

## 3.3 Skill 概览（每个 Skill 的目的与输入/输出简介）

下面按流水线顺序列出常见 Skill，并对每个 Skill 给出一句话目的、主要输入输出与预期行为：

1. pdf2text
   - 目的：把 PDF（或 DOCX）转换成带位���信息的纯文本，尽可能还原阅读顺序
   - 主要输入：raw_pdf（文件或文件路径）
   - 主要输出：text_segment（段落/行/页面的文本，带页码与坐标）、confidence
   - 预期行为：检测列、忽略页眉页脚、识别图表占位并标注

2. ocr (可选)
   - 目的：对扫描或图像 PDF 执行 OCR，生成可抽取文本
   - 主要输入：raw_pdf 或 image_page
   - 主要输出：text_segment（来自图像的文本）、confidence
   - 预期行为：仅在 pdf2text 无法提取文本或置信度过低时触发

3. segmenter（结构分段）
   - 目的：将文档文本分为结构化片段（标题、作者区、摘要、正文、参考文献等）
   - 主要输入：text_segment
   - 主要输出：document_segments（按类型分组的文本块）
   - 预期行为：为下游抽取 Skill 提供更清晰的上下文边界

4. title-extraction
   - 目的：从 document_segments 中识别并规范化论文标题
   - 主要输入：document_segments
   - 主要输出：title（text，normalized）、confidence
   - 预期行为：处理换行断句、大小写、特殊字符等

5. author-extraction
   - 目的：识别作者姓名及其顺序、附带标记（如上标编号）
   - 主要输入：document_segments（作者区���或 text_segment
   - 主要输出：authors_list（带原始字符串、正规化字段、position、affiliation_refs）
   - 预期行为：支持多种姓名格式（东亚姓名、复合姓）、输出标准化形式

6. affiliation-extraction
   - 目的：从作者区或脚注中抽取机构原文与候选标准机构
   - 主要输入：authors_list（含 affiliation_refs）、document_segments
   - 主要输出：affiliations（原文、候选校名、候选 ID、confidence）
   - 预期行为：产出候选集供归一化 Skill 进一步决策

7. abstract-extraction
   - 目的：提取并清洗摘要文本
   - 主要输入：document_segments
   - 主要输出：abstract_text、keywords_candidates（可选）

8. keyword-extraction
   - 目的：抽取或生成关键词列表（基于规则或模型）
   - 主要输入：title、abstract_text、full_text（可选）
   - 主要输出：keywords（含 source: author/model）

9. reference-extraction
   - 目的：从参考文献区块识别每条引用字符串（raw reference）
   - 主要输入：document_segments（reference section）
   - 主要输出：references_raw_list（字符串数组，带索引）
   - 预期行为：根据段落/编号识别条目边界

10. reference-parser
    - 目的：把 raw reference 解析成结构化字段（authors, title, venue, year, pages, doi 等）
    - 主要输入：references_raw_list
    - 主要输出：references_parsed（结构化引用条目）、confidence
    - 预期行为：优先抽取 DOI/ArXiv，若 DOI 存在则可直接链接外部元数据

11. doi-resolver / external-metadata-fetcher
    - 目的：用 DOI / title /作者信息查询外部服务（CrossRef、SciHub、arXiv API）获取权威元数据
    - 主要输入：references_parsed（含 doi 或可疑 title）
    - 主要输出：references_enriched（补全后的引用记录，含外部 id）

12. normalizer（名称/机构归一化）
    - 目的：将作者名与机构名映射到规范化表征（例如：统一大小写、拆分中英名、匹配 ROR/GRID）
    - 主要输入：authors_list、affiliations
    - 主要输出：authors_normalized、affiliations_normalized（含候选 id 与匹配置信息）
    - 预期行为：提供 Top-N 候选与置信度，支持人工复核流程

13. linker（记录链接 / 引文链接）
    - 目的：在内部知识库或文献库中为条目寻找匹配（去重、指向同一论文的链接）
    - 主要输入：title、authors_normalized、year、doi
    - 主要输出：linked_record_id（或创建新记录）、match_score
    - 预期行为：���顾精确 DOI 匹配与模糊标题匹配的平衡

14. quality-check（质量检查）
    - 目的：对关键字段进行一致性/完整性检查（例如：作者数量、是否有 DOI、年份是否合理）
    - 主要输入：合并后的条目（包含上述各 Skill 输出）
    - 主要输出：qc_report（字段缺失、低置信度提示、人工复核列表）

15. exporter（存储/导出）
    - 目的：将清洗后的结构化元数据导出为目标格式（JSON-LD、CSV、数据库写入）
    - 主要输入：linked_record（或 enriched_record）
    - 主要输出：存储结果或导出文件信息

## 说明与使用建议

- 高内聚、低耦合：每个 Skill 应聚焦有限职责，内部可使用复杂模型或规则，但外部接口应保持简洁。
- 置信度与候选集：对于具有不确定性的步骤（机构匹配、作者消歧），Skill 应返回候选 Top-N 与置信度而不是单一强制选择，以便编排器或人工参与做最终决策。
- 可配置性：manifest 中的 config 字段允许同一 Skill 在不同场景（比如对高质量 PDF 批处理 vs 扫描件）用不同策略。
- 链接与外部依赖：当 Skill 依赖外部 API（CrossRef、ROR）时，应在 manifest 中声明依赖与失败回退策略（缓存、降级到本地匹配）。
