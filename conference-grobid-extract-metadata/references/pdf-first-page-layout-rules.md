# PDF 首页版式规则

本文档定义 GROBID header TEI 与 PDF 首页证据合并时使用的版式分类。先识别标题区域和
作者区域结构，再选择对应规则；会议 strategy 只负责提供会议特有边界，不能替代版式识别。

## 通用使用顺序

1. 解析 GROBID header TEI，保留标题、作者顺序、机构、邮箱和角色的初始结果。
2. 读取首页及必要时第二页的文本行、文本块、横纵坐标、字号、链接和脚注。
3. 识别标题区域类型和作者区域类型。一篇论文可同时匹配排列、关联和补充位置规则。
4. 按字段合并：可靠 TEI 字段不因较弱 PDF 候选而整体覆盖；PDF 只补充或修复有闭合证据的字段。
5. 将原始候选、版式关系、采用结果和拒绝原因写入 evidence/candidate/decision 产物。

## 标题区域：6 类

### 1. 标准单行标题

**特征**：标题位于首页上部，通常为较大字号，下方紧接作者区域。

**处理规则**：

- 优先采用干净的 GROBID 标题，PDF 单行标题用于核对和缺失回填。
- 遇到可信作者行、机构行、邮箱、Abstract、Keywords 或正文标题时结束标题区域。
- 规范化连字、异常空格和 PDF 字形，不改变标题词序。

**禁止条件**：会议名、页码、ISBN、DOI、版权或下载水印不能作为标题。

### 2. 多行长标题

**特征**：标题由连续 2 至 3 行组成，各行字号、对齐和垂直间距相近。

**处理规则**：

- 按页面从上到下合并连续标题行，保留正常单词间空格和标题标点。
- 作者或机构行出现后停止；末行疑似作者时先从标题候选移出，再进入作者识别。
- GROBID 标题被截断时，可用完整 PDF 标题行替换。

**禁止条件**：不能跨越作者区域继续拼接；不能仅因换行或连字符将两个无关文本块合并。

### 3. 标题上方存在会议页眉

**特征**：真正标题之前存在会议名称、论文集名称、版权、ISBN、DOI、页码或下载水印。

**处理规则**：

- 先按会议和出版平台噪声标记过滤页眉，再识别第一个连续标题块。
- 标题候选应位于作者区域之前，并具有标题词形或相对较大的主字号支持。
- TEI 标题包含页眉前缀时，只删除能够明确识别的前缀。

**禁止条件**：不得使用模糊的“看起来不像标题”规则删除未知文本。

### 4. 主标题与副标题组合

**特征**：主标题和副标题通过冒号、破折号或上下两行连接。

**处理规则**：

- 保留冒号、破折号及副标题；上下两行属于同一标题块时合并。
- 仅当冒号或分隔符之后出现明确作者、机构或模板信息时，才截断污染部分。
- 比较 GROBID 与 PDF 候选的完整程度，优先保留完整主副标题。

**禁止条件**：不能因为标题中包含多个冒号就自动删除合法副标题。

### 5. 标题与作者行粘连

**特征**：GROBID 标题末尾包含作者姓名、多个逗号、分号、上标或机构片段。

**处理规则**：

- 检查标题是否包含已识别作者的完整姓名或连续姓氏。
- 优先从 PDF 首页标题行重建；无法重建时，在第一个明确作者标记前截断。
- 被移出的文本重新作为作者区域候选，不直接丢弃。

**禁止条件**：没有作者姓名或版面边界证据时，不能仅凭逗号数量截断标题。

### 6. 首页为封面或特殊出版页

**特征**：第一页主要为出版封面、会议说明或简化信息，第二页才出现完整标题和作者区。

**处理规则**：

- 分别提取第一页和第二页的标题、作者候选。
- 优先选择能够形成完整“标题—作者”结构且噪声更少的页面。
- 另一页面可补充出版信息，但不与正式标题直接拼接。

**禁止条件**：不能固定认为第一页或第二页始终更可靠，也不能把两个页面的标题串联。

## 作者区域：10 类

### 1. 单行连续作者

**特征**：多名作者在同一行，通过逗号、分号、中点或 `and` 分隔。

**处理规则**：

- 按页面从左到右保留作者顺序，不按字母排序。
- 拆分作者分隔符，保留姓名内部连字符、缩写和重音字符。
- 去除姓名后的机构上标、星号、信封或通讯标记，标记另行交给关联和角色规则。
- GROBID 作者列表完整时，PDF 只用于姓名标点恢复和字段补充。

**禁止条件**：机构、邮箱、会议名和版权文本不能作为作者；无 PDF 证据时不能合并相邻姓名。

### 2. 多行作者排列

**特征**：作者分布在两行或多行，同一行可能横向排列多名作者。

**处理规则**：

- 根据纵坐标分行，同一行按横坐标从左到右，多行按从上到下确定顺序。
- 不使用 PDF 内部文本流顺序替代视觉阅读顺序。
- 机构、地址、邮箱、Abstract 或正文标题出现后结束作者行发现。
- 合并后执行规范化姓名去重和缩写重复检查。

**禁止条件**：第二行只有机构或地点时不能作为作者行；列边界不清时不能强制重排可靠 TEI 顺序。

### 3. 作者卡片式排版

**特征**：每位作者与其机构、地点、邮箱形成相对封闭的局部区域，块间有明显空间分隔。

**处理规则**：

- 以可信作者姓名块为卡片锚点，以“下一个可信作者名”作为当前卡片边界。
- 同一卡片内允许“作者—邮箱—机构”和“作者—机构—邮箱”两种顺序。
- 卡片内机构和邮箱优先关联当前作者；地点行只追加到已识别机构。
- 只有全部已有作者均精确锚定、新作者有唯一局部机构支持且阅读顺序闭合时，才重建作者列表。

**禁止条件**：卡片关系不完整时只补字段，不能整体覆盖 TEI；跨卡片全宽机构不能归给中间作者。

### 4. 横向列对齐作者—机构矩阵

**特征**：作者、机构、地点和邮箱按两列、三列或多列对齐，没有明显卡片边框或块间距。

**处理规则**：

- 以作者姓名横坐标建立作者列，将下方横向重叠比例最高的机构和邮箱关联到该列。
- 同一行从左到右，多行矩阵从上到下确定作者顺序。
- 机构或邮箱必须与作者列形成稳定重叠；多列线性化文本应依赖坐标重建。
- 横跨多个作者列的机构作为共享候选，等待共享或编号规则确认。

**禁止条件**：不能按 PDF 文本流顺序关联；列边界重叠或歧义时不能按中心点强制分配。

### 5. 作者与机构纵向堆叠

**特征**：作者、机构、部门、地址、邮箱按作者逐组纵向排列。

**处理规则**：

- 可信作者姓名开启一个作者块，下一名作者开启前结束当前块。
- 块内机构、部门、地点和邮箱按类型保存；部门不能替代主体机构，地点不能单独作为机构。
- Abstract、Keywords 或正文标题结束整个作者区域。
- GROBID 顺序完整时优先补机构和邮箱；只有块关系闭合时恢复缺失作者。

**禁止条件**：单个公共邮箱不能默认归给当前作者；无主体机构时不能把城市或国家写成机构。

### 6. 作者上标与集中机构列表

**特征**：作者集中排列并带数字或符号上标，下方集中列出带编号的机构。

**处理规则**：

- 作者区和机构列表分别识别，建立作者上标到机构起始编号的多对多映射。
- 一个作者的多个上标保留为多个独立机构；多名作者可共享同一编号。
- 机构列表结束于邮箱、Abstract、Keywords 或正文标题之前。
- 只有全部作者引用符号与机构定义闭合时，才用完整 PDF 映射替换错误 TEI 机构。

**禁止条件**：邮编、楼号、年份和地址数字不能作为机构编号；无显式编号的顺序关系只能作候选。

### 7. 多个作者组分别共享机构

**特征**：一组作者后紧随一个机构块，随后出现下一组作者及另一机构块。

**处理规则**：

- 连续作者组成当前作者组，紧随其后的机构关联到组内全部作者。
- 下一组可信作者出现时结束上一组机构范围。
- 多个连续机构作为该组整体候选；存在编号时优先使用编号映射。
- 只有作者组与机构块在空间上连续且边界闭合时才传播。

**禁止条件**：不能把上一组机构传播到后续作者；不能跨越摘要、正文标题或明显分隔内容关联。

### 8. 全体作者共享机构或邮箱

**特征**：完整作者集合后只有一个无歧义机构块，或出现花括号共享域名邮箱。

**处理规则**：

- 无新作者组且只有一个基础机构时，将其关联到完整作者集合。
- `{alice,bob}@example.edu` 拆分后，邮箱局部名必须唯一匹配作者。
- 单个作者带额外符号机构时，基础机构和符号机构按闭合规则分别处理。
- 共享主体机构不等于共享部门，机构层级按 PDF 实际文本保留。

**禁止条件**：单个公共邮箱不能分配给全部作者；邮箱数、作者数或顺序不闭合时不能按序写回。

### 9. 首页脚注或页侧信息

**特征**：作者区只列姓名，页脚或页侧通过姓名、数字、星号、匕首符号说明机构或作者角色。

**处理规则**：

- 脚注姓名必须与顶部作者列表匹配，只补机构、通讯作者、共同贡献或工作期间机构信息。
- 明确的 `affiliated with`、`was at ... during this work` 只关联被点名作者。
- `corresponding author` 和 `equal contribution` 只形成角色关系，不形成机构关系。
- `now at`、`currently with` 等作为补充证据，不直接覆盖论文发表时主要机构。

**禁止条件**：脚注姓名不能重复加入作者列表；脚注中单独出现的机构不能传播给全体作者。

### 10. 首页与后续页面分别出现作者信息

**特征**：第一页为简化作者区或出版页，第二页出现更完整作者、机构、邮箱或角色信息。

**处理规则**：

- 分别提取各页面作者候选，比较作者数量、姓名完整性、顺序和机构覆盖率。
- 选择结构最完整的一组作为作者基线，另一页面只补充明确缺失字段。
- 同一作者跨页按规范化姓名合并，不直接拼接两个作者列表。
- 作者顺序以完整正式作者区域为准，补充后重新计算 rank 和角色字段。

**禁止条件**：不能固定以第二页覆盖第一页；重复作者不能新增，后续页面无明确人名时不能推断新作者。

## 机构区域：10 类

机构区域规则负责从 PDF 首页恢复可追溯的原始作者机构，不在此阶段完成机构标准名称、
ROR 或国家知识库归一化。部门、主体机构和地点的进一步结构化交给后续机构规范化阶段。

### 1. 单行完整机构

**特征**：机构名称及其城市、国家位于同一行，或一行中只有完整机构名称。

**处理规则**：

- 将完整文本作为一条原始机构记录，保留名称、层级和地点的原始顺序。
- 城市和国家可以保留在原始字符串中，并作为后续结构化证据。
- 逗号优先解释为机构层级或地址分隔，不能单独触发多机构拆分。

**禁止条件**：不能在 GROBID 提取阶段用标准名称覆盖 PDF 原文，也不能把逗号后的地点当成新机构。

### 2. 多行机构与地址

**特征**：机构、部门、城市和国家在连续多行中显示，机构名称本身也可能换行。

**处理规则**：

- 合并同一作者区域内字号、列位置和间距连续的机构行。
- 以 `of`、`for`、`and` 等连接词结尾的行优先继续拼接下一行。
- 地点行追加到最近且关系明确的机构；下一作者、下一编号、邮箱或摘要结束当前机构块。

**禁止条件**：不能把所有相邻行无条件合并；换行本身不是多机构分隔依据。

### 3. 部门—主体机构层级

**特征**：Department、School、Faculty、Laboratory 等下属单位与 University、Institute、
Company 等主体机构连续出现。

**处理规则**：

- 保留“下属单位—主体机构”的完整原始层级和页面顺序。
- 下属单位与紧随其后的主体机构组合为一条作者机构记录。
- 后续规范化阶段可将主体机构用于统计，并将部门或实验室保留为子单位。

**禁止条件**：没有主体机构证据时，不能自动把普通部门或学院当成主要机构；不能只保留大学而丢弃原始部门层级。

### 4. 编号或符号机构列表

**特征**：机构条目以数字、星号、匕首等标记开头，并与作者上标对应。

**处理规则**：

- 机构标记只在条目起始位置有效；同一标记后连续多行属于当前机构。
- 新标记、邮箱、Abstract、Keywords 或正文标题结束当前机构条目。
- 只有作者引用标记和机构定义全部闭合时，才写回编号或符号映射。

**禁止条件**：邮编、门牌号、年份和地址数字不能作为机构编号；作者角色符号不能自动解释为机构符号。

### 5. 一名作者对应多个机构

**特征**：作者具有多个机构上标，或机构之间存在明确分号、编号或独立文本块。

**处理规则**：

- 每个明确机构分别保留，并按页面关联顺序生成独立 `affiliation_rank`。
- 多上标映射不得合并为一个不可区分的机构字符串。
- 分号、完整编号映射或两个独立机构块可作为拆分依据。

**禁止条件**：普通逗号不能作为多机构拆分依据；联合实验室或复合机构的完整名称不能被过度拆分。

### 6. 全体作者共享机构

**特征**：完整作者集合后只有一个无歧义机构块，或全部作者引用同一机构标记。

**处理规则**：

- 没有新作者组、局部卡片冲突和未定义符号时，将机构关联到全部作者。
- 全部作者使用相同上标时，可作为闭合共享关系证据。
- 部分作者存在额外上标时，基础机构与附加机构分别保留。

**禁止条件**：同页只发现一个机构不等于全体共享；机构必须位于摘要前作者区并与完整作者集合形成闭合关系。

### 7. 作者卡片或矩阵中的局部机构

**特征**：机构位于作者卡片内部，或与作者列在横坐标上稳定对齐。

**处理规则**：

- 卡片式按局部作者边界关联，矩阵式按横向重叠和纵向位置关联。
- 机构下方地点行追加到同一机构；一个局部机构只关联空间关系明确的作者。
- 横跨多个作者列的机构转为共享候选，等待共享或编号规则确认。

**禁止条件**：不能只用最近距离或中心点分配机构；边界不闭合时不能覆盖已有 TEI 机构。

### 8. 首页脚注或页侧机构

**特征**：作者区未完整列出机构，页脚或页侧通过作者姓名、编号或符号说明机构关系。

**处理规则**：

- 脚注作者必须与顶部作者列表唯一匹配，明确的 `is with`、`affiliated with` 可建立关系。
- `was with ... during this work`、`now at`、`currently with` 作为带语义的补充证据保存。
- 页侧机构只有在姓名、编号或符号关系明确时才使用。

**禁止条件**：脚注中未点名作者的机构不能传播给全体作者；现工作单位不能直接覆盖论文发表时机构。

### 9. 被 PDF 文本层打散的机构

**特征**：一个机构被拆成多个行或坐标块，出现 `University, China`、`Science and, Technology`
等残片，或完整名称被分页文本层切断。

**处理规则**：

- 结合相邻坐标、字号、列位置、连接词和作者卡片关系重组固定语法片段。
- 高置信编号、符号或局部卡片映射可以替换明显碎片化的 TEI 机构。
- 重组前后的文本块、坐标和采用理由必须保留在证据中。

**禁止条件**：不能仅因相邻就拼接；无法形成完整机构的残片不能作为最终原始机构传给后续规范化。

### 10. 纯地址、城市和国家信息

**特征**：文本块只包含城市、州、省、邮编、街道或国家，不包含可信组织名称。

**处理规则**：

- 将地点行追加到最近且关系明确的机构，国家可作为后续国家归属的 PDF 直接证据。
- 邮编、门牌号和纯地点不能建立作者机构关系。
- 没有可关联机构时保留地点候选，不写入主体机构字段。

**禁止条件**：城市、国家或地址不能单独作为机构；不能依据地点常识反推一个未在 PDF 出现的组织。

## 邮箱区域：8 类

邮箱先作为独立字段提取，再依据作者姓名、局部版面、脚注语义或完整组关系建立归属。
已有可靠 TEI 邮箱只接受更强证据校正，不由较弱 PDF 候选覆盖。

### 1. 单作者完整邮箱

**特征**：作者卡片、机构块或脚注中出现一个语法完整的邮箱，并可唯一对应一名作者。

**处理规则**：优先保留 TEI `<email>`；TEI 为空时，用邮箱局部名、同卡片关系或脚注明确姓名
完成映射。邮箱统一去除外围标点，但保留局部名中的点、连字符和加号。

**禁止条件**：单个邮箱不能仅因距离最近就分配给作者；邮箱局部名同时匹配多人时不得写入作者字段。

### 2. 多个完整邮箱集中排列

**特征**：多个完整邮箱位于作者列表或机构列表下方，可能同一行或连续多行显示。

**处理规则**：先逐个使用唯一局部名匹配；存在封闭的作者列、作者卡片或明确顺序关系时，再按对应
关系补空邮箱。已有非空邮箱与候选冲突时保留原值并记录冲突。

**禁止条件**：邮箱数量、作者数量或顺序不闭合时不能单纯按出现顺序分配。

### 3. 花括号共享域名

**特征**：邮箱写成 `{alice,bob}@example.edu` 或相同含义的局部名集合加公共域名。

**处理规则**：拆分花括号内的局部名，逐个补全公共域名；每个局部名必须唯一匹配一名作者，且
拆分后的邮箱必须通过完整邮箱语法检查。

**禁止条件**：不能把花括号内容识别为作者；存在空局部名、重复归属或无法匹配项时，整组不按顺序写回。

### 4. 局部邮箱与共享域名分离

**特征**：邮箱写成 `{alice@, bob@mail.}example.edu`，或局部名、部分子域名与末尾域名被分开显示。

**处理规则**：只拼接结构明确的花括号组；保留局部项已有的 `@` 或子域名片段，再追加公共后缀。
拼接后逐项进行完整邮箱检查和唯一作者匹配。

**禁止条件**：不能依据常见机构域名猜补缺失字符；后缀位置不明确或任一项不能闭合时不自动恢复。

### 5. 作者卡片或矩阵中的邮箱

**特征**：邮箱位于独立作者卡片内，或在横向矩阵中位于某一作者列下方。

**处理规则**：卡片式以局部作者边界关联；矩阵式以横向重叠、纵向顺序和列边界关联。邮箱可位于
机构之前或之后，同一卡片内的顺序不固定。

**禁止条件**：跨越多个作者列的邮箱不能归给中心点最近作者；卡片或列关系不闭合时只能保留候选。

### 6. 脚注或通讯作者邮箱

**特征**：邮箱出现在首页底部、页侧或 `Corresponding author`、`Contact` 等说明中。

**处理规则**：脚注明确姓名时按姓名映射；只有邮箱时仍需通过已有作者邮箱、唯一局部名或脚注符号
建立关系。邮箱归属与通讯作者角色分别判断。

**禁止条件**：脚注邮箱不能自动证明通讯作者身份；`corresponding author` 说明中的邮箱也不能传播给
未被姓名、符号或语义指向的其他作者。

### 7. 被换行或文本层打散的邮箱

**特征**：一个邮箱被换行、空格或相邻文本块拆开，或者花括号组在 PDF 文本层中分为多个片段。

**处理规则**：只在相邻坐标、同一字号、同一列或明确花括号结构支持下，恢复固定形式的断行和片段；
恢复结果必须通过完整邮箱语法检查，并能唯一归属作者。保留原始片段和拼接依据。

**禁止条件**：当前规则不自动解释任意 `name at domain dot edu` 等混淆写法，也不能跨作者卡片或跨列
拼接邮箱残片。

### 8. 公共邮箱或无法明确归属的邮箱

**特征**：出现项目邮箱、实验室公共邮箱、投稿联系邮箱，或邮箱局部名无法唯一匹配作者。

**处理规则**：保留为论文级候选或提取证据，不写入具体作者邮箱；后续若出现明确姓名、符号或卡片
关系，再按更强证据建立归属。

**禁止条件**：不能因为邮箱位于完整作者集合下方就分配给全部作者；公共邮箱也不能用于推断通讯作者。

邮箱证据优先级为：TEI 明确邮箱，其次是 PDF 作者卡片或矩阵邮箱、姓名明确的脚注邮箱、
花括号共享域名邮箱、可闭合恢复的邮箱片段，最后是论文级邮箱候选。较弱证据不得覆盖已有可靠邮箱。

## 作者角色：7 类

作者角色以最终作者顺序和 PDF/TEI 中的明确文本、符号、信封或脚注关系为依据。邮箱只作为
已明确角色说明中的身份匹配证据，不能单独产生角色。

### 1. 第一作者

**特征**：作者列表中出版顺序第一位的作者。

**处理规则**：作者顺序最终确定后，将 `order=0` 的作者设为 `first_author=true`。若存在明确共同一作，
共同一作集合中的作者也设为 `first_author=true`，并按共同一作导出规则处理 rank。

**禁止条件**：不能按姓名字母顺序、机构顺序、邮箱顺序或网页展示顺序重新推断第一作者。

### 2. 共同一作

**特征**：出现 `co-first`、`joint first`、`shared first`，或明确说明前两位、前三位、前 N 位作者共同贡献。

**处理规则**：接受明确姓名列表、作者符号到脚注的闭合映射，以及 `first two/three/N authors` 范围。
命中作者设置 `equal_contribution=true`、`co_first_author=true` 和 `first_author=true`。

**禁止条件**：只有 `equal contribution` 关键词而没有姓名、符号或范围时，不能默认前两位作者共同一作。

### 3. 一般共同贡献

**特征**：明确说明若干作者贡献相同，但这些作者集合不构成以第一作者为起点的共同一作范围。

**处理规则**：将被明确点名或符号映射的作者设为 `equal_contribution=true`；当该集合不包含第一作者时，
保持 `co_first_author=false`，不改变第一作者集合和作者 rank。

**禁止条件**：不能把所有 equal contribution 都解释为共同一作，也不能把未被说明覆盖的作者加入集合。

### 4. 通讯作者

**特征**：出现 `corresponding author`、`author for correspondence`、明确姓名、脚注符号、信封标记，
或 LNCS 文本层中的等价信封编码。

**处理规则**：通过明确姓名、作者符号到角色脚注、信封标记或通讯说明中的已知作者邮箱定位作者，
设置 `corresponding=true`。

**禁止条件**：作者具有邮箱不等于通讯作者；机构联系人、项目邮箱和模板中的 `Contact` 不能直接产生角色。

### 5. 多名通讯作者

**特征**：通讯说明明确列出多名作者，多个作者共享通讯符号，或多个信封标记分别落在作者姓名后。

**处理规则**：分别解析每个姓名、符号或信封标记，允许同一论文多名作者设置 `corresponding=true`；
保持原作者顺序，不因通讯身份调整 rank。

**禁止条件**：发现一个通讯作者后不能停止解析后续角色证据；共享机构或共享邮箱不能自动扩展通讯作者集合。

### 6. 同一脚注包含多个角色

**特征**：PDF 文本层把共同贡献和通讯作者说明合并在同一行，例如两个带不同符号的连续句子。

**处理规则**：按句号、脚注符号或角色关键词切分说明；分别建立共同贡献和通讯作者映射，同一作者也可
同时具有多种角色。

**禁止条件**：不能把整行只按第一个符号解释，也不能把后一段出现的作者姓名错误归入前一角色。

### 7. 没有明确角色说明

**特征**：首页、必要补充页和 TEI note 中均没有可定位的共同贡献或通讯作者证据。

**处理规则**：只依据最终顺序标记普通第一作者；`co_first_author`、`equal_contribution` 和
`corresponding` 保持 `false`。

**禁止条件**：不能用邮箱存在、作者位置、星号外形、机构数量或常见出版习惯补猜角色。

## 字段覆盖边界

- 标题、作者名、作者顺序、机构、邮箱和角色分别判断，不能整体覆盖。
- PDF parser 识别更多作者但明显丢失机构或邮箱时，只合并缺失字段。
- 可靠 TEI 作者列表与 PDF 候选冲突时，保留 TEI，并在候选和证据中记录差异。
- 只有作者集合、阅读顺序、机构/邮箱关系和全部引用符号闭合时，PDF 才能重建作者列表或替换机构映射。
- 不依赖姓名字母顺序、最近中心点、邮箱域名常识或同页任意机构名称建立作者关系。
